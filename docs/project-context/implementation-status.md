# Implementation status

> **Warning (2026-11-13):** The "Implemented" labels below describe code that exists, not verified end-to-end behavior. The [restructuring audit](../restructuring/01-audit-findings.md) found blockers that stop these features working at runtime. Seeded logins (F1) and browser CORS for auth (F2) were fixed and verified on 2026-11-14 (Phase 0b). Cross-service Kafka delivery (F3) was fixed and verified on 2026-11-14 (Phase 1): a new order reaches `PAID` in about 1 s, with payment, shipment, delivery, fulfillment and notification records and catalog `SOLD`. Compensation paths (cancel, payment failure, expiry, sale conflict, archive rules) were fixed in Phase 2 and verified by `make smoke` (22/22 checks) on 2026-11-14. It also found saga gaps (S1, S2, S5, S7, S9). This table will be rewritten as the [restructuring phases](../restructuring/02-target-architecture-and-requirements.md#4-implementation-phases-order-matters) land.

## Feature status (Post-Refactoring)

| Feature | Status | Evidence and qualification |
|---|---|---|
| API Gateway (`gateway-service`) | Implemented | Publishes the application API, validates RS256 JWTs (user-service issues them), applies edge role checks, and routes requests to backend services. |
| User management and authentication | Implemented | User-service owns BCrypt credentials, integer-ID user CRUD, and RS256 token issuance; the gateway only validates tokens. User accounts support self profile/password updates, admin CRUD, and soft deactivation; default `ADMIN` and `USER` accounts are seeded/migrated by Flyway. |
| Internal service boundary | Implemented for local Compose | Backend HTTP ports are not published; user-service requests require a shared gateway token. Production mTLS is still an infrastructure deployment requirement, not configured here. |
| Pet catalog CRUD/search & sync | Implemented and verified (2026-11-14) | Seeded with 6 sample pets. `availabilityStatus` is a read-only copy synced from inventory. `DELETE` archives (`RETIRED`, hidden, not orderable; 409 for reserved/sold pets). Catalog events go through an outbox. |
| Order create/list/get/cancel & Saga | Implemented and verified (2026-11-14) | `OrderStateMachine` (`CREATED → PAYMENT_PENDING → CONFIRMED`; `CANCELLED`/`FAILED` terminal). Confirmed only after inventory sold the pets (`PetsSold`). Every unsuccessful ending publishes `OrderCancelled`/`OrderFailed`. Smoke-tested: happy path, payment declined, cancel during charge, expiry during charge. |
| Inventory reserve/expiry/sold | Implemented and verified (2026-11-14) | All-or-nothing reservation (unknown pets fail with `PET_NOT_FOUND`). Sells on payment **only if still reserved for the order**, otherwise reports `InventorySaleConflict` (no double sale). Releases on `OrderCancelled`/`OrderFailed`, configurable expiry, `RETIRED` for archived pets, read-only HTTP. |
| Payment | Implemented and verified (2026-11-14) | Charges the order total through a simulated `PaymentGateway` (no fallback amount). Refunds a successful charge when the order is cancelled or failed (`REFUNDED`, `PaymentRefundedEvent`) and never charges a closed order. Per-order advisory lock prevents charge/cancel interleaving (smoke-tested with slow charges). |
| Notifications & Shipping/Delivery/Fulfillment | Implemented | Propagates real `customerId` from `OrderConfirmedEvent`, exposes `PUT /api/v1/shipments/order/{orderId}/delivered`, and updates existing `FulfillmentRecord` rows on `DELIVERED` transitions. |
| Transactional outbox + Kafka conventions | Implemented and verified (2026-11-14) | All 8 producing services (now including catalog) write outbox rows only. The shared `platform-commons` relay publishes after broker acknowledgement. Consumers use plain JSON, retry, then dead-letter to `<topic>.DLT` (verified live with a poison message), and deduplicate via `processed_events`. See [Event catalog](./events.md). |
| React Storefront | Implemented | Includes fixed 1-indexed MUI pagination, `?species=` URL query filtering, auto-login on registration, and an Orders & Tracking page (`/orders`). |
